# 账期短信提醒列表

## 适用场景

列表字段 `账期短信提醒列表`（`type: list`）。模板这样使用每一行：

- `{% if item.提醒类型 == "活动到期套餐资费变更" %}` …于`{{item.提醒时间}}`下发`{{item.提醒次数}}`次活动到期提醒短信，内容：`{{item.短信内容}}`…
- `{% if item.提醒类型 == "语音超额提醒" %}` / `"流量超额提醒"`：在`{{item.账期月}}`使用过程中，我公司于`{{item.提醒时间}}`发送`{{item.提醒次数}}`次…短信提醒。

每一行固定 5 列（列名必须完全一致）：

| 列 | 内容 |
|---|---|
| 账期月 | `yyyy年M月`，月份不补零，如 `2026年10月` |
| 提醒类型 | 只能是 `活动到期套餐资费变更`、`语音超额提醒`、`流量超额提醒` |
| 提醒时间 | 同月同类型所有短信的发送时间，按时间正序，每个格式化为 `yyyy年M月d日 HH时mm分ss秒`，多个用顿号 `、` 连接 |
| 提醒次数 | 同月同类型短信条数（数字字符串，如 `"2"`） |
| 短信内容 | 仅“活动到期套餐资费变更”填写：同月该类型所有短信原文按发送时间正序用换行 `\n` 连接；两类超额提醒填空字符串 `""` |

## 需要的入参

| 入参 | 要求 |
|---|---|
| 手机号码 | 必须是 11 位数字 |
| 账单 | 必须**完全符合** `^(\d{6})\$(\d{6})$`，如 `202610$202611`；两个月份都必须是合法年月（月 01～12），且结束月份不早于开始月份 |

任一不满足时**不要调用接口、不要修正或猜测账期**，字段提交 `status="not_found"`、`value=null` 并写明原因。

## 查询方法（用 `expand_period` 解析并逐月调用）

1. 校验 `账单` 符合 `^(\d{6})\$(\d{6})$` 且开始月份 `<=` 结束月份后，直接调用 `expand_period(period=账单)`——平台会自动将双段 `yyyyMM$yyyyMM` 按闭区间展开为首尾之间的全部连续月份（升序排列，如 `202607$202610` 展开为 `["202607","202608","202609","202610"]`）。
2. 从 `expand_period` 返回的 `monthRanges` 中直接读取每个月的 `month`、`start`（当月首日 `000000`）与 `end`（当月末日 `235959`），对每个月调用 `call_api("querySMSSendInfo", {"手机号码": 手机号码, "开始时间": start, "结束时间": end})`。互不依赖的月份可以并行调用。
3. 任一月份 `ok=false`（非“无短信记录”的业务失败、网络错误等）→ 整个字段提交 `status="not_found"`、`value=null` 并写明哪个月失败（不能把接口报错当作空列表）。
4. 某月 `ok=true` 且 `count=0`（含“无短信记录”）是正常的，表示该月无短信记录。

## 整理规则（与 Java 完全一致）

收集全部成功月份的 `resultIds` 后合并筛选：

1. `smsSendTime` 去掉非数字后必须**恰好 14 位**且是合法日期时间，否则丢弃；前 6 位账期月必须落在 `[开始月份, 结束月份]` 闭区间内（可用 `query_result` 的 `resultIds=[...]` 配合 `{"column": "smsSendTime", "op": "between", "value": 开始月份, "endValue": 结束月份, "prefixLen": 6}` 过滤）。
2. 按账期月从小到大，每个月依次检查三类（顺序固定，同一条短信可以同时计入多类）：
   - **活动到期套餐资费变更**：正文同时包含 `到期提醒` **和** `资费标准`（`where` 同时带两个 `contains` 条件）；
   - **语音超额提醒**：正文包含 `通话使用提醒`；
   - **流量超额提醒**：正文包含 `流量使用提醒`。
   关键词都是原文包含判断（不清洗）。可用 `query_result(resultIds=[...], where=[...], orderBy={"column": "smsSendTime", "desc": false}, limit=100)` 一步跨月筛选并按发送时间正序排列。
3. 某月某类没有短信 → 不输出该行。
4. 有短信 → 输出一行，列值按上表计算：
   - 每个发送时间用 `format_date(value=smsSendTime, fromPattern="yyyyMMddHHmmss", toPattern="yyyy年M月d日 HH时mm分ss秒")` 转换，直接使用工具输出，再按发送时间正序用 `、` 连接（不要自己改写格式）；
   - 账期月用 `format_date(value="<yyyyMM>", fromPattern="yyyyMM", toPattern="yyyy年M月")` 转换；
   - 提醒次数 = 该行包含的短信条数，转为数字字符串（如 `"2"`），在 `reasoning` 中列出命中的 `resultId` 与 `row`。
5. 行顺序：先按账期月升序；同一月份内固定为 `活动到期套餐资费变更` → `语音超额提醒` → `流量超额提醒`。

示例：10 月有 `20261005123001`（到期提醒+资费标准）、`20261008092010` 与 `20261015180602`（通话使用提醒）、`20261020101010`（流量使用提醒）；11 月有 `20261103081020`（流量使用提醒）→ 4 行：

| 账期月 | 提醒类型 | 提醒时间 | 提醒次数 | 短信内容 |
|---|---|---|---|---|
| 2026年10月 | 活动到期套餐资费变更 | 2026年10月5日 12时30分01秒 | 1 | （该短信原文） |
| 2026年10月 | 语音超额提醒 | 2026年10月8日 09时20分10秒、2026年10月15日 18时06分02秒 | 2 | |
| 2026年10月 | 流量超额提醒 | 2026年10月20日 10时10分10秒 | 1 | |
| 2026年11月 | 流量超额提醒 | 2026年11月3日 08时10分20秒 | 1 | |

## 提交要求

- **有命中记录时**：提交 `status="found"`，`value` 为行对象数组（每行五个键：`提醒类型`、`账期月`、`提醒时间`、`提醒次数`、`短信内容`）；`evidence` 引用每一行包含的每条短信记录（`{"type":"api","resultId":...,"row":...,"column":"smsSendTime"}`，资费变更行再引用 `smsContent`），以及用到的 `expand_period`、`query_result`、`format_date` 的 `{"type":"tool","callId":...}`。
- **全部月份查询成功（`ok=true`）但无任何命中提醒短信时**：**必须提交 `status="found"`、`value=[]`**，并在 `evidence` 中附上结果为 0 行的查询证据：
  - 若调用 `query_result` 筛选后 `total == 0`（三类提醒筛选均 `total == 0`），引用这些 `total == 0` 的 `query_result` 返回的 `{"type":"tool","callId":"..."}`；
  - 若所有月份 `call_api` 均直接返回 `count == 0`，引用各月 `call_api` 返回的 `{"type":"tool","callId":"..."}`（或 `count == 0` 结果的 `{"type":"api","resultId":"...","row":0,"column":""}`）；
  - 严禁在原接口 `count > 0` 时仅引用 `type="api"`，也严禁引用 `load_skill` 的 `callId`！`reasoning` 写明“各月接口查询成功，无符合条件的提醒短信”。
- **仅当缺少合法入参（号码非 11 位、账单格式不合法）或任一月份接口报错（`ok=false`）时**：提交 `status="not_found"`、`value=null`。
- 不得输出账单区间以外、或未命中上述关键词的短信。
